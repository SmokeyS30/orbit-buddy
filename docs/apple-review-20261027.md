# Apple review correction checklist (local preparation)

Apple's reviewed version was 1.1 build 20261032, submission `5435fb13-8f88-48ea-8b99-286e2ab6c344`. This repository's current native project still identifies build 20261031. The exact source of the reviewed archive must be identified on the Mac before creating the next build. These steps have **not** been performed in this cloud workspace.

## Before capture or resubmission

1. On the Mac, verify the archive's commit, version, build number, bundled `public` assets, and StoreKit plugin against the reviewed and proposed source. Build a new synchronized archive containing the consent and Plans changes. Do not reuse the rejected archive.
   Coordinate server consent enforcement with that client rollout: an older installed native bundle has no consent control, and existing accounts default to no permission after the database migration. Deploying the server gate by itself would block those clients' AI features until they update to a bundle with the new choice.
2. On a real supported iPad, install that exact archive through the intended review distribution. Use a synthetic review account with no personal data. Confirm registration or sign-in, the AI disclosure before the first AI request, Not now blocking AI work while non-AI account areas remain available, and Allow enabling a chat response. In Safety, withdraw and confirm another AI request is blocked.
   Voice input in the proposed client uses consent-gated server transcription; browser SpeechRecognition was removed because its service recipient was not identified. Verify the microphone path on the actual iPad build. Confirm the deployed text endpoint is OpenAI or a named Microsoft Azure OpenAI hostname; custom compatible endpoints are blocked until their recipient is disclosed.
3. Confirm the always-visible **Plans** button reaches the Basic, Plus, and Unlimited cards for a signed-in account, even when no quota has been used. Tap Plus to find its Monthly and Yearly choices; these and Basic Monthly and Unlimited Monthly correspond to the four existing products. In the StoreKit sandbox, verify all four products load from App Store Connect, show the correct local prices, and can complete and restore under a test Apple ID. Product availability, prices, payment processing, and production subscription enforcement were **not** changed in this branch.
4. Capture genuine in-use screenshots from the exact new iPad build: a signed-in Today conversation, AI permission screen, Plans chooser, Plus Monthly/Yearly details, and a useful in-app screen such as Tasks or Safety. Replace login-only images with app-in-use images, as [App Review guideline 2.3.3](https://developer.apple.com/app-store/review/guidelines/) requires. For an iPadOS app, [Apple's current screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/) require at least one 13-inch iPad screenshot: accepted portrait sizes are 2064 × 2752 or 2048 × 2732 pixels (landscape reverses them). Apple can scale that required slot to smaller displays. If adding an 11-inch slot, capture at an accepted size listed on that page for the specific display. Do not stretch an 11-inch image to fill the 13-inch slot. Use genuine captures from the running app, with private data and credentials removed before capture.
5. In App Review notes, provide a working synthetic review account, clear steps to reach Plans from the top bar, a description of the permission prompt and Safety withdrawal control, and any sandbox account or configuration prerequisites Apple requests. Do not include real credentials in repository files. Check the reviewer's account can reach the relevant screens without owner-only permissions or quota exhaustion.
6. Verify in the actual iPad build, then submit the new archive and metadata. These native, StoreKit, App Store Connect, and physical-device checks are outside this local cloud task and remain release gates.

The local server guard covers model requests and server voice transcription. A request already sent to a provider cannot be recalled when permission is withdrawn. No claim about provider training or retention is made here.
